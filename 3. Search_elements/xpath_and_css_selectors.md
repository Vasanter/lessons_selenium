# ШПАРГАЛКА: XPATH И CSS-СЕЛЕКТОРЫ

**XPath и CSS-селекторы** — основные инструменты для поиска элементов в DOM-структуре HTML-документов при автоматизации тестирования и веб-скрейпинге.

---

# БЛОК 1. XPATH (XML Path Language)

Язык для навигации по структуре XML/HTML-документов. Нужен для поиска сложных динамических элементов и движения вверх/вниз по DOM-дереву.

## Базовая навигация XPath

* **Абсолютный путь** — начинается с `/`, описывает полный путь до элемента, ломается при любом изменении, в тестах почти не используют.
* **Относительный путь** — начинается с текущего узла или `//`, гибкий и устойчивый, постоянно используют в тестах.

**Синтаксическая формула:** `Xpath = //tagname[@attribute='value']`

| Символ | Значение | Пример | Что выберет |
| :---: | :--- | :--- | :--- |
| **/** | Корень документа (абсолютный путь) | `/html/body/div` | `div` внутри `body` внутри `html` |
| **//** | Любой уровень вложенности | `//div` | Все `div` в документе |
| **.** | Текущий узел | `.//a` | Все ссылки внутри текущего узла |
| **..** | Родительский узел | `../@class` | Класс родителя текущего узла |
| **@** | Атрибут | `//a/@href` | Все `href` у ссылок |
| *** ** | Любой элемент | `//div/*` | Все дочерние элементы `div` |

## Оси XPath

**Оси** — это направление поиска элементов относительно текущего узла.

| Ось | Значение | Пример |
| :--- | :--- | :--- |
| **self::** | Сам узел | `//div/self::div` |
| **child::** | Дочерние элементы | `//div/child::span` |
| **descendant::** | Любые потомки | `//div/descendant::a` |
| **parent::** | Родитель | `//span/parent::div` |
| **ancestor::** | Предки | `//span/ancestor::div` |
| **following::** | Все элементы после данного | `//div/following::div` |
| **following-sibling::** | Следующие соседи | `//div/following-sibling::div` |
| **preceding::** | Все элементы до данного | `//div/preceding::div` |
| **preceding-sibling::** | Предыдущие соседи | `//div/preceding-sibling::div` |

## Функции XPath

**Функции Xpath** — это готовые команды, которые можно использовать внутри условий.

| Функция | Что делает | Пример |
| :--- | :--- | :--- |
| **contains(строка, подстрока)** | Проверяет, содержит ли строка подстроку | `contains(@class, 'btn')` |
| **starts-with(строка, начало)** | Проверяет, начинается ли строка с указанного префикса | `starts-with(@href, 'https://')` |
| **normalize-space(строка)** | Убирает лишние пробелы | `//div[normalize-space(text())='Отправить']` |
| **string-length(строка)** | Возвращает количество символов в строке | `string-length(@title) > 50` |
| **count()** | Возвращает количество найденных узлов | `count(//div) > 10` |
| **position()** | Возвращает позицию текущего элемента в наборе (с 1) | `[position()=3]` или `[position()>2]` |
| **last()** | Возвращает номер последнего элемента в наборе | `[last()]` или `[last()-1]` |
| **text()** | Ищет элементы на основе текста внутри них | `//a[text()='Регистрация']` |

## Операции XPath

Операции позволяют соединять условия и делать вычисления прямо внутри XPath.

| Категория | Оператор | Пример |
| :--- | :---: | :--- |
| **Логические** | `and` | `@type='text' and @required` |
| | `or` | `@type='text' or @type='password'` |
| | `not()` | `not(@disabled)` |
| **Сравнение** | `= !=` | `@id='login'` или `position()!=last()` |
| | `< > <= >=` | `count(div)>5` or `position()<=3` |
| **Арифметика** | `+ - *` | `position()+1` или `last()-2` |
| | `mod` | `position() mod 2 = 0` (чётные)<br>`position() mod 2 = 1` (нечётные) |

## Условия (предикаты) XPath

Квадратные скобки `[]` — это фильтр, который оставляет из всех найденных элементов только те, что удовлетворяют условию внутри.

| Условие | Что выбирает |
| :--- | :--- |
| `[@href]` | Есть атрибут href |
| `[@type='text']` | Точное значение атрибута |
| `[contains(@class, 'active')]` | Класс содержит active |
| `[starts-with(@href,'https')]` | Ссылки по https |
| `[not(@disabled)]` | Активные элементы |
| `` / `[last()]` | Первый / последний элемент |
| `[position() mod 2 = 1]` | Нечётные элементы |
| `[@type='text' or @type='password']` | Текстовые поля и пароли |

## Рекомендации для работы с XPath

### Самые статичные атрибуты:
1. `@aria-label` — Хорошо, так как это атрибут доступности и редко меняется.
2. `@click-event-target` — Если этот атрибут уникален для элемента, его можно использовать.
3. `@class` — Хорошо, если класс уникален или используется в уникальном контексте.
4. `@id` — Идеально, если ID уникален и статичен.
5. `@data-qa-` — Специально созданные для автоматизации атрибуты, обычно статичные и уникальные.
6. `@role` — Хорошо для определения типа элемента, но может не быть уникальным.
7. `data-tab`, `data-current` и подобные* — Подходят, если они уникальны и не меняются динамически.

### Самые динамические атрибуты:
1. `text()` — Может изменяться, но для некоторых элементов (например, кнопок) текст может быть стабилен и уникален. Но если сайт мультиязычный, то такой вариант сами понимаете, не прокатит.
2. `href` — Может меняться, особенно если ссылки динамически генерируются.
3. `[2]` — Порядковые номера могут быть очень ненадёжными, особенно если структура DOM меняется.

### Практические советы:
1. **Используй комбинации атрибутов:** Если один атрибут не уникален, попробуйте комбинировать несколько.
   * *Пример комбинирования условий:*
     ```xpath
     //div[@class='example' and @data-qa='unique']
     ```
2. **Избегай порядковых номеров:** Они очень ненадёжны. Лучше использовать другие критерии для выбора элементов.
3. **Учитывай возможные изменения:** Планируйте XPath так, чтобы минимизировать влияние возможных изменений на странице. Например, избегайте длинных цепочек предков, если структура страницы может изменяться.

> **Важно знать:** SVG нельзя использовать как локатор! XPath его не видит, так как svg находится в другом пространстве имён, да есть обходные пути, но не делайте так, за них цепляться нельзя. Можно так: `//*[local-name()='svg']` - но лучше не нужно!

**И самое главное!** Смотрите вокруг, ищите вложенности и прочие связи элементов! Что в чем и где лежит! Ни в коем случае не ограничивайтесь одним элементом. После нажатия Inspect анализируйте всю структуру страницы, а не только выбранный элемент!

# БЛОК 2. CSS-СЕЛЕКТОРЫ

Используются браузерами для применения стилей к элементам. В автотестах они работают быстрее, чем XPath, и имеют более лаконичный синтаксис, но не умеют двигаться вверх к родительским элементам или искать по тексту (без специальных расширений).

## Поиск по атрибутам в CSS

| Селектор | Что находит | Пример |
| :--- | :--- | :--- |
| `[type]` | Наличие атрибута (выберет элементы, у которых есть атрибут `type`) | `input[type]` |
| `[type='hidden']` | Полное и точное совпадение значения атрибута | `input[type='hidden']` |
| `[type*='idde']` | Частичное совпадение (подстрока находится в любом месте значения) | `[type*='idde']` |
| `[type^='hidd']` | Значение атрибута начинается с указанной строки | `[type^='hidd']` |
| `[type$='dden']` | Значение атрибута заканчивается указанной строкой | `[type$='dden']` |
| `[class\|='form']` | Значение в точности равно `form` **или** начинается с `form-` (с дефисом) | `[class\|='form']` |
| `[class~='requiredField']` | Выберет элемент, если `requiredField` — один из классов в списке через пробел | `input[class~='requiredField']` |

## Навигация и связи в CSS

| Селектор / Комбинатор | Значение | Пример |
| :--- | :--- | :--- |
| *Пробел* | Любой потомок (любой уровень вложенности) | `form[method='post'] label` (найдет `label` внутри `form`, даже глубоко внутри) |
| **>** | Прямой потомок (только на один уровень ниже) | `div > span` (найдет `span`, только если он непосредственный «ребенок» `div`) |
| **+** | Ближайший сосед (следующий сразу за элементом на том же уровне) | `form + div` (найдет `div`, который расположен строго после `form`) |
| **~** | Любой следующий сосед (на том же уровне вложенности) | `h1 ~ p` (найдет все параграфы `p`, идущие после заголовка `h1`) |
| `:has()` | Поиск элемента, содержащего определенного потомка *(псевдокласс)* | `div:has(span.error)` (выберет `div`, внутри которого есть `span` с классом `error`) |

*Примечание: Прямого движения «вверх» к родителю (аналога `/..` или `/parent::` из XPath) в чистом CSS не существует.*
